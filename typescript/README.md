# @etalii/lark

A port of the [Lark](https://github.com/lark-parser/lark) parsing toolkit (version 1.3.1) to TypeScript. Grammars
mean exactly what they mean in Lark: the trees, token types, positions and errors are the same. A shared conformance
suite, generated by Python Lark, checks this for this package and its [.NET](https://www.nuget.org/packages/EtAlii.Lark)
and [Rust](https://crates.io/crates/etalii-lark) siblings.

It covers:

- Lark's EBNF grammar language, with `%import`, `%ignore`, `%declare`, `%override` and `%extend`, templates, and the
  `common`, `unicode`, `python` and `lark` grammars (bundled, so they work in the browser too).
- The Earley, LALR(1) and CYK parsers.
- The basic, contextual, dynamic and dynamic-complete lexers, custom lexers, and post-lexers such as the `Indenter`.
- Tree building: `?rule` and `_rule` inlining, `!rule` token keeping, aliases, `maybePlaceholders`, positions,
  priorities, and ambiguity handling (resolve or explicit `_ambig` trees).
- Transformers and visitors.
- Error handling: Lark's `UnexpectedToken`, `UnexpectedCharacters` and `UnexpectedEOF` with their positions and
  expected terminals, `matchExamples`, error recovery, and the interactive LALR parser.

Terminals are written in Python's regular expression syntax, as in Lark; the package translates them into JavaScript
regular expressions with the same meaning (Unicode classes, `$`, `\Z`, `\b`, case folding, inline flags, and so on).
It has no dependencies, and works in Node.js (20 or later) and in browsers.

```sh
npm install @etalii/lark
```

## Quick start

```ts
import { Lark } from '@etalii/lark';

const parser = new Lark(
  `
  start: WORD "," WORD "!"
  %import common.WORD
  %ignore " "
  `,
  { parser: 'lalr' },
);

const tree = parser.parse('Hello, World!');
console.log(tree.pretty());
```

`new Lark(grammar, options)` is the equivalent of Python's `Lark(grammar, **options)`, with the options in camelCase:
`start`, `parser` (`'earley'`, `'lalr'`, `'cyk'`), `lexer` (`'auto'`, `'basic'`, `'contextual'`, `'dynamic'`,
`'dynamic_complete'`, or a custom lexer object), `ambiguity`, `priority`, `propagatePositions`, `maybePlaceholders`,
`keepAllTokens`, `strict`, `regexFlags`, `postlex`, `lexerCallbacks`, `importPaths` and `sourcePath`.

## Trees

A parse returns a `Tree` with `data` (the rule name) and `children`: subtrees, `Token`s, or `null` for an unmatched
`[optional]`. With `propagatePositions`, `tree.meta` holds the position. Offsets (`startPos`, `endPos`) index into the
JavaScript string, and columns count UTF-16 code units, so `text.slice(token.startPos, token.endPos)` is the token's
text; Lark counts code points instead, which only differs for characters outside the Basic Multilingual Plane.

## Transformers and visitors

A `Transformer` turns a tree into a value, bottom-up, without recursing, so deep trees are fine. Name a method after
each rule or alias (it gets the transformed children and the tree's `meta`) and after each terminal (it gets the
token):

```ts
import { Lark, Token, Transformer } from '@etalii/lark';

class Sum extends Transformer<number> {
  start(children: number[]) {
    return children.reduce((a, b) => a + b, 0);
  }
  NUMBER(token: Token) {
    return Number(token.value);
  }
}

const parser = new Lark('start: (NUMBER ","?)+\n%import common.NUMBER', { parser: 'lalr' });
console.log(new Sum().transform(parser.parse('1,2,3'))); // 6
```

Trees without a method are rebuilt with their transformed children (override `default` to change that), and a method
can return `Discard` to remove the node. An error in a method is wrapped in a `VisitError`. A `Visitor` calls the
method named after each subtree's rule, bottom-up with `visit` or top-down with `visitTopdown`.

## Errors

Parse errors are Lark's: `UnexpectedCharacters` when no terminal matches, `UnexpectedToken` when the parser doesn't
expect a token, and `UnexpectedEOF` at a premature end, all subclasses of `UnexpectedInput` and `LarkError`, with
`line`, `column`, `getContext(text)` and the expected terminals. Invalid grammars raise a `GrammarError`.

With the LALR parser, `parser.parse(text, start, onError)` recovers from errors: `onError` gets the error and an
`InteractiveParser`, and returns whether to continue. `parser.parseInteractive(text)` gives the interactive parser
directly.

## Imports

`%import common.NUMBER` and the other bundled grammars work everywhere. Other imports are resolved by the loaders in
`importPaths` (tried in order), such as `new FileSystemLoader(directory)` (Node.js) or `new MemoryLoader({ 'path.lark':
text })`, and relative imports (`%import .other.RULE`) by the directory of `sourcePath`.
