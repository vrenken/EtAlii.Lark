# etalii-lark

A port of the [Lark](https://github.com/lark-parser/lark) parsing toolkit (version 1.3.1) to Rust. Grammars mean
exactly what they mean in Lark: the trees, token types, positions and errors are the same. A shared conformance
suite, generated by Python Lark, checks this for this crate and its [.NET](https://www.nuget.org/packages/EtAlii.Lark)
and TypeScript siblings.

It covers:

- Lark's EBNF grammar language, with `%import`, `%ignore`, `%declare`, `%override` and `%extend`, templates, and the
  `common`, `unicode`, `python` and `lark` grammars.
- The Earley, LALR(1) and CYK parsers.
- The basic, contextual, dynamic and dynamic-complete lexers, custom lexers, and post-lexers such as the `Indenter`.
- Tree building: `?rule` and `_rule` inlining, `!rule` token keeping, aliases, `maybe_placeholders`, positions,
  priorities, and ambiguity handling (resolve or explicit `_ambig` trees).
- Transformers and visitors.
- Error handling: Lark's `UnexpectedToken`, `UnexpectedCharacters` and `UnexpectedEOF` with their positions and
  expected terminals, `match_examples`, error recovery, and the interactive LALR parser.

Terminals are written in Python's regular expression syntax, as in Lark; the crate translates them for
[`regex-automata`](https://crates.io/crates/regex-automata), and uses [`fancy-regex`](https://crates.io/crates/fancy-regex)
for the lookarounds and backreferences it can't handle.

```sh
cargo add etalii-lark
```

## Quick start

```rust
use etalii_lark::{Lark, ParserKind};

fn main() -> Result<(), etalii_lark::Error> {
    let parser = Lark::builder(r#"
            start: WORD "," WORD "!"
            %import common.WORD
            %ignore " "
        "#)
        .parser(ParserKind::Lalr)
        .build()?;

    let tree = parser.parse("Hello, World!")?;
    println!("{}", tree.pretty());
    Ok(())
}
```

`Lark::new(grammar, LarkOptions { .. })` is the equivalent of Python's `Lark(grammar, **options)`: every Lark option is
a field of `LarkOptions` and a method of the builder.

## Trees

A parse returns a `Tree` with `data` (the rule name) and `children`, each a `Node`: a subtree, a `Token`, or `Missing`
for an unmatched `[optional]`. With `propagate_positions`, `tree.meta()` holds the position. Byte offsets
(`start_pos`, `end_pos`) index into the Rust string, while lines and columns count characters, as in Lark.

## Transformers and visitors

A `Transformer` turns a tree into a value, bottom-up, without recursing, so deep trees are fine:

```rust
use etalii_lark::{Lark, Meta, ParserKind, Token, Transformer};

struct Calc;

impl Transformer for Calc {
    type Output = f64;
    type Error = std::num::ParseFloatError;

    fn tree(&mut self, data: &str, children: Vec<f64>, _meta: &Meta) -> Result<f64, Self::Error> {
        Ok(match data {
            "add" => children[0] + children[1],
            "mul" => children[0] * children[1],
            _ => children[0],
        })
    }

    fn token(&mut self, token: Token) -> Result<f64, Self::Error> {
        token.value.parse()
    }
}

fn main() -> Result<(), etalii_lark::Error> {
    let parser = Lark::builder(r#"
            ?start: sum
            ?sum: product | sum "+" product -> add
            ?product: NUMBER | product "*" NUMBER -> mul
            %import common.NUMBER
            %ignore " "
        "#)
        .parser(ParserKind::Lalr)
        .build()?;

    assert_eq!(Calc.transform(parser.parse("1 + 2 * 3")?)?, 7.0);
    Ok(())
}
```

A `Visitor` is called for each subtree, bottom-up (`visit_all`) or top-down (`visit_topdown`).

## Typed code generation

The [`etalii-lark-derive`](https://crates.io/crates/etalii-lark-derive) crate generates a typed API for a grammar at
compile time: a parser, a wrapper for each kind of tree with an accessor for each child, and a typed visitor whose
methods get their children already converted to the result types you map.

```rust,ignore
use etalii_lark_derive::{lark_grammar, lark_result};

#[lark_grammar(file = "src/calc.lark", parser = "lalr")]
#[lark_result(f64, "add", "mul", "number")]
pub mod calc {}

impl calc::Visitor for Evaluator {
    type Error = std::num::ParseFloatError;
    fn visit_add(&mut self, _: calc::AddNode<'_>, sum: f64, product: f64) -> Result<f64, Self::Error> {
        Ok(sum + product)
    }
    // ...
}

let value = Evaluator.visit_start(&calc::parse("1 + 2 * 3")?)?;
```

See its README for the details. `etalii_lark::codegen::Generator` generates the same code from a build script.

## Errors

```rust
use etalii_lark::{Error, Lark, ParserKind};

fn main() -> Result<(), etalii_lark::Error> {
    let parser = Lark::builder("start: \"a\" \"b\"").parser(ParserKind::Lalr).build()?;
    match parser.parse("aa") {
        Err(Error::UnexpectedToken(e)) => {
            assert_eq!((e.line, e.column), (1, 2));
            assert!(e.expected.contains("B"));
        }
        other => panic!("{other:?}"),
    }
    Ok(())
}
```
